# OctoAcme Project Management Docs

This directory contains the guidance OctoAcme uses to plan, deliver, release, and improve cross-functional projects.

## Project management process overview

OctoAcme follows a customer-first, iterative delivery process with clear ownership and data-informed decisions. Work moves from initiation and stakeholder alignment through planning, execution and tracking, release and deployment, and retrospective-driven continuous improvement. The process defines responsibilities for Product Managers, Project Managers, developers, QA, and stakeholders; uses regular communication and risk management; and applies quality checks throughout delivery.

Projects begin with a one-pager, success metrics, stakeholders, an initial timeline, and known risks. Once approved, the team creates a prioritized and estimated backlog with acceptance criteria, dependencies, milestones, and a Definition of Done. During execution, teams track work on a project board, use standups and delivery syncs to surface blockers, and validate changes through reviews, automated checks, testing, and manual QA when appropriate. Releases require passing quality and security checks, smoke testing, release notes, and rollback planning. Retrospectives after sprints, releases, and incidents turn lessons into owned, time-bound improvement actions.
